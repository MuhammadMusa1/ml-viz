# Лаборатория ML — правила проекта

Интерактивные визуализации к курсу Machine Learning для подростков 12–17 лет (24 урока, 2 занятия в неделю).
Каждая страница = одна тема курса. Ученик двигает точки, крутит ползунки и видит, как модель принимает решения.

**Эталон: `viz/knn/index.html`.** Новые страницы делай по его образцу: та же структура, те же классы CSS, тот же стиль кода.

## Жёсткие правила

1. **Только чистый HTML + CSS + JavaScript.** Без React, без сборки, без npm, без CDN, без внешних шрифтов.
2. **Работает офлайн с `file://`.** Учитель копирует папку на флешку и открывает `index.html` в классе без интернета.
   - Данные подключать через `<script src="../../data/xxx.js">` (`window.XXX = ...`), **не через `fetch()`**: fetch с file:// не работает.
   - Никаких ES-модулей (`type="module"` с file:// тоже ломается). Только обычные `<script>` и IIFE.
3. **Все расчёты настоящие.** Модель реально считается в браузере, никаких заранее зашитых «красивых» результатов. Это обязательный стандарт курса.
4. **Числа совпадают с Colab.** Если страница показывает точность или метрику, она должна совпадать с тем, что ученик получит в sklearn на тех же данных:
   - датасет `load_penguins().drop(columns=['sex']).dropna().reset_index(drop=True)` = 342 строки;
   - разбиение `train_test_split(..., test_size=0.2, random_state=42)` уже записано в `data/penguins.js` (столбцы `is_test`, `split_pos`);
   - validation для подбора параметров: `train_test_split(X_train, y_train, test_size=0.25, random_state=42)` → 204 + 69, тоже в `data/penguins.js` (столбцы `is_val`, `val_pos`);
   - масштабирование считается **только по train** (как `StandardScaler.fit(X_train)`), чтобы не было утечки данных;
   - ничьи в голосовании решаются как в sklearn (класс, который раньше по алфавиту).
   - KNN: выбирай признаки и K так, чтобы у соседей не было одинаковых расстояний на границе K. Иначе sklearn разбивает ничью по-разному в зависимости от `algorithm`, порядка столбцов, DataFrame/массива и даже компьютера, и с Colab не сверить. Длина крыла — целое число, на ней ничьих много. Проверка «на прочность» — как для урока 11: сравнить JS со всеми `algorithm` sklearn.
   - Сверяй результат JS с Python-скриптом (пример: `tools/check_knn.py`). Известное исключение: KNN со включённым масштабом и K=7 даёт на сайте 68/69, а в sklearn 67/69. Причина: два соседа на одинаковом расстоянии, sklearn выбирает между ними внутренним порядком.
5. **Основной датасет курса — Palmer Penguins.** Titanic не использовать. Другие датасеты только если тема их требует (например, MNIST для свёртки, тексты для LLM). Маленькие, встроенные в `data/*.js`.
6. **Не называть термин «переобучение» раньше урока 6.** На странице KNN ученик сам видит, что при K=1 граница рваная, но слово «overfitting» не звучит. На странице Train/Test термин вводится после того, как ученик увидел проблему сам.
7. **sklearn `Pipeline` ≠ HF `pipeline`.** На страницах уроков 10+ явно указывать разницу, где она уместна.
8. **Параметры не подбирают по test.** Если ученик выбирает K, глубину, конвейер и т.п. — выбор идёт по validation, а test открывается один раз в конце (как в играх Train/Test и Pipeline). Где без этого никак, явно пишем, что так делать нельзя.
9. **Маленький test — шумный.** 1 пингвин из 69 = 1.5%. Разницу в 1 пингвина не называем «победой» или «поражением».

## Словарь (одно понятие — одно название на всех страницах)

- «Точность (accuracy) — доля верных ответов» при первом упоминании на странице. Не путать с precision (урок 11).
- **train** (обучающие / «учёба»), **validation** («пробный экзамен»), **test** («экзамен»).
- **Стандартное отклонение** (std) — «насколько пингвины обычно отличаются от среднего». Не просто «отклонение».
- **Карта решений** — у каждой карты подпись `.note`: «каждая точка фона окрашена в вид, который модель назвала бы пингвину в этом месте».
- **Gini** — «смешанность группы: 0 = все одного вида».
- Английский термин — с переводом рядом: «Глубина дерева (max_depth)», «Масштаб (StandardScaler)». В сообщениях игр без внутренних названий алгоритмов (не «CART»).
- Если показываем accuracy классификатора — рядом точка отсчёта: «ленивая» модель, которая всегда называет самый частый вид (на test это 35 из 69 = 51%).
- Код в «Для любопытных» запускается целиком: с загрузкой данных, `X`, `y` и `train_test_split`.

## Структура страницы (сверху вниз)

1. `eyebrow`: «Урок N · Фаза». Если у урока несколько страниц — «Урок N · часть k из m · Фаза» (k — порядок в `catalog.js`). Текст **не пишем** ни в разметке, ни в `STR`: в странице только пустой `<p class="eyebrow"></p>`, `core.js` заполняет его по каталогу (`MLViz.lessonLabel` + название фазы). Кнопку Colab в «Для учителя» (`#colabLink`) тоже заполняет `core.js`.
2. `h1`: название темы.
3. `.analogy-box`: **аналогия сначала**, одна-две фразы, без формул (KNN = соседи, дерево = «20 вопросов», лес = голосование класса, нейросеть = ученик, исправляющий ошибки, attention = на какие слова смотреть, LLM = умный автодополнитель).
4. `.viz-layout`: слева `.viz-main` с главным canvas (`.stage`), справа панель управления (`.panel`). Дополнительные графики и списки — `.stage.viz-extra`: на телефоне они уходят под панель, а главный график и управление остаются рядом.
5. Минимум один **игровой элемент**: «угадай раньше модели», соревнование, «подбери параметр лучше соседа». Кнопка режима называется «Игра: …». У игры есть конец (10 раундов или N попыток) и итог, правила счёта написаны в тексте игры.
6. «Как это работает»: 3–5 нумерованных шагов простыми словами.
7. «Попробуй сам»: 4–5 заданий-вопросов, которые ведут к выводу (наводящие, без готовых ответов).
8. «Типичные ошибки новичка» — 2–3 пары «Кажется / На самом деле». Пишутся в `catalog.js` (`myths`), на страницу их вставляет `core.js` перед первым `<details>`. Числа — только из `tools/check_*.py`.
9. `<details>` «Для любопытных: формула»: математика и код sklearn **в самом конце**.
10. `<details>` «Для учителя»: данные, как использовать на уроке (0–10 мин вовлечение), вопросы для обсуждения, ссылка на Colab.
11. «Что дальше» — связь со следующим уроком и кнопка «Дальше». Текст в `catalog.js` (`bridge`), блок добавляет `core.js` в конец страницы.

## Код

- Модели, которые считаются как в sklearn (KNN в Pipeline, дерево, `StratifiedKFold`), — в `assets/models.js` (`MLModels`); страницы с кросс-валидацией (уроки 12, 19) берут их оттуда.
- Общие функции в `assets/core.js` (`MLViz.fitCanvas`, `scale`, `pointer`, `rng`, `shuffle`, `t`, `applyI18n`, `renderHeader`, `drawAxes`, `plotPad`, `range`, `setPressed`). Не дублировать их в страницах.
- Оси графиков — только через `MLViz.drawAxes` и отступы `MLViz.plotPad(w, символов_в_делениях_Y)`: шрифт растёт под проектор.
- Переключатели режимов и видов — контейнер `.seg` (режимы: `.seg.modes`) и `MLViz.setPressed(...)` (`aria-pressed`). Класс `.primary` — **только** для кнопок действия («Лучшая прямая», «Сдать экзамен»).
- Подключать `assets/catalog.js` на каждой странице урока: по нему в шапке появляются ссылки «‹ Урок N · Урок N ›».
- Canvas, на котором что-то **тянут**, получает класс `drag` (блокирует прокрутку пальцем). Остальные canvas листают страницу на телефоне — класс не ставить.
- Всё, что делается кликом по canvas, должно быть доступно и кнопками в панели (клавиатура, программы экранного доступа).
- Текст на canvas не мельче 13 px; мелкие клетки без чисел (числа — в расчёте рядом). Тёмный текст на светлом фоне.
- **Игры — только через `MLViz.quiz`** (`assets/core.js`). Игра = N раундов, экзамен «подбери и сдай один раз» = 1 раунд. Страница даёт `round(q)` (вопрос раунда) и вызывает `q.answer(очки, html)`; варианты ответа — `q.choices(контейнер, подписи, верно(i), приВыборе(i, ok))`. Компонент сам ведёт счёт, заголовок `#gameStep`, результат `#gameResult` (`role="status"`), кнопку `#nextBtn` («Дальше» → «Итог» → «Сыграть ещё ↺») и итог `text.final(q)`. Без `final` после последнего ответа сразу «Сыграть ещё». Свой цикл раундов на странице не писать.
- После игры настройки ученика в «Исследуй» восстанавливаются.
- Общие классы из `style.css`: `.sub` (подзаголовок блока), `.divider`, `.tbl-wrap` (широкая таблица с прокруткой внутри), `.viz-extra { min-width: 0 }`. Не копировать их в страницы.
- `aria-label` и прочие подписи для программ экранного доступа тоже берутся из `STR`.
- Общие стили в `assets/style.css`. Новые классы добавлять туда, только если они пригодятся больше чем одной странице.
- Canvas рисовать через `MLViz.fitCanvas(canvas, aspect)`: учитывает ширину контейнера и devicePixelRatio. Перерисовка по `resize` с задержкой.
- Указатель через `pointerdown/move/up` (мышь + тач). Страница должна работать на телефоне и на проекторе.
- Код короткий, с комментариями на русском. Комментарий объясняет «зачем», а не «что».
- Тяжёлые расчёты (карта решений) кешировать по ключу параметров.

## Дизайн

- Тёмная тема курса: фон `#17132E`, акценты фиолетовый / циан / бирюзовый (переменные в `style.css`).
- **Токены дизайн-системы v1** — в начале `style.css`: нейтрали `--n-950…--n-100`, роли (`--surface-1/2/3`, `--text-strong`, `--text`, `--text-2`, `--text-muted`, `--line`, `--line-strong`, `--control-line`), бумага журнала (`--paper`, `--ink`), шрифты `--fs-*` / `--lh-*`, отступы `--s-*` (сетка 4 px), радиусы `--r-*`, глубина `--e-*`, стиль графиков `--plot-*`. В новом коде используем их; старые имена (`--bg-2`, `--card`, `--muted`…) оставлены как ссылки на токены, их читают страницы и canvas.
- Режим проектора — класс `.projector` на `<html>`: шрифты крупнее, текст на ступень светлее. На телефоне (≤ 600 px) шрифты на ступень меньше — тоже через токены, отдельный `font-size` для `body` не задавать.
- **Акцент интерфейса — тёплый белый** `--accent` (бумага журнала) с тёмным текстом `--accent-ink`. Цветной акцент не берём: яркие оттенки заняты видами и частями данных. Акцент — только заливка (кнопка `.primary`, прогресс, выбранное); как цвет текста он почти не отличается от обычного, слова им не выделяем.
- Цвета видов пингвинов везде одинаковые: Adelie `--adelie`, Chinstrap `--chinstrap`, Gentoo `--gentoo`.
- Цвета видов **не используются** для интерфейса и метрик. Части данных: train `--c-train` (розовый), validation `--c-val` (зелёный), test `--c-test` (белый). Большие числа — белые, если не относятся к одной из этих частей.
- Смысловые цвета: отрицательные числа — `--c-neg` (оранжевый), «подозрительное / необычное» (выброс, NaN, случайное слово) — `--c-odd`. Свои hex-цвета для этих смыслов на страницах не заводить.
- Пингвинов test рисуем кольцами; «не видел» в других смыслах (вне рюкзака в лесу) — пунктиром, чтобы не путать с test.
- Кнопки на телефоне не ниже 44 px (уже в `style.css`).
- Шрифт Calibri (с системными запасными), код Consolas.
- Крупно и контрастно: страницу показывают на проекторе.

## Языки

- Языки: **русский** (основной) и **таджикский** (`tg`, переключатель «Рус / Тоҷ» в шапке). Все тексты страницы лежат в объекте `STR = { ru: {...}, tg: {...} }` вверху скрипта, в разметке только ключи `data-i18n="key"` / `data-i18n-html="key"`. Новые и изменённые тексты пишем на русском, потом `node tools/i18n.js export` → перевод → `import tg` (без перевода ключ показывается по-русски).
- **Не писать русский текст прямо в HTML-разметке** (кроме `<title>` и названий видов). Иначе перевод потом придётся выковыривать.
- Таджикский позже: добавить `tg: {...}` в каждый `STR` и в `assets/catalog.js`, потом добавить `'tg'` в `LANGS` в `core.js`. Переключатель языка появится автоматически.
- Перевод делается через `tools/i18n.js`: `export` выгружает все тексты в `i18n/ru/*.json`, переводчик (Gemini, правила в `i18n/PROMPT.md`) кладёт файлы в `i18n/tg/`, `import tg` проверяет ключи, HTML-теги и `{подстановки}` и вставляет перевод между метками `tg:start`/`tg:end` (повторный импорт заменяет их). `check` находит русский текст в коде мимо `STR`. После правки текстов страницы — снова `export` и перевести изменившиеся ключи.

## Словарь терминов и прогресс

- `window.GLOSSARY` в `catalog.js`: первое упоминание термина на странице (аналогия, разделы, `<details>`) само становится подчёркнутой кнопкой с подсказкой. Новый термин курса — добавить туда (основа слова + определение из «Словаря» выше).
- Урок отмечается «пройденным», когда игра на странице доиграна до конца (`MLViz.quiz` сам вызывает отметку). Отметки — в `localStorage` этого браузера, на главной счётчик «Пройдено N из M» и «Сбросить отметки».

- Раздел `book/`: `book/index.html` (библиотека, обычная страница со `STR`), `book/ml/` и `book/ml2/` — **сгенерированы** из книг Word скриптом `tools/build_book.py`, `book/python/` — учебник Python как есть (без внешних шрифтов).

- Ноутбуки Colab: `notebooks/chNN.ipynb` (их тоже кладёт `build_book.py`), адрес — `window.COURSE.colab` в `catalog.js`. Colab открывает их с GitHub, поэтому ссылки работают только после `git push`.

## Python-разминки

- `warmup/index.html?lesson=N` — 5–7 минут Python перед уроком: «что выведет?», «в какой строке ошибка?», «собери программу». Только конструкции, которые нужны в ноутбуке этого урока.
- Задания пишутся в `tools/build_warmup.py`; `python tools/build_warmup.py` запускает каждую программу настоящим Python и пишет `data/warmup.js` (вывод, строку ошибки, все верные порядки строк). Руками — только неверные варианты; `data/warmup.js` руками не правим.
- Тексты заданий — в `STR` страницы: `x_<id>` (объяснение), `g_<id>` (условие «собери»), `topic_<тема>`. Скрипт проверяет, что ключи есть.
- Новый урок с разминкой: добавить номер в `COURSE.warmup` в `catalog.js` — по нему на странице урока в «Что дальше» появится кнопка (скрипт сверяет список).

## Проверка перед тем, как сказать «готово»

1. Открыть страницу в браузере (Playwright или вручную), проверить, что в консоли нет ошибок.
2. Проверить ширину 1280 и 390 px.
3. Если есть метрики — сверить с sklearn скриптом в `tools/`.
4. Проверить, что страница открывается с `file://` (без локального сервера).
