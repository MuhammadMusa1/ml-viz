Приложение V. MLOps на минималках

Обучить модель — половина дела. Что происходит дальше, когда модель нужно сохранить, запустить в работу и поддерживать? Это область MLOps. Здесь — самые основы на понятном уровне.

Сохранение модели

Обученную модель не нужно переобучать каждый раз — её сохраняют в файл и загружают, когда нужно. Для sklearn это делается в одну строку через joblib.

import joblib

# Сохранить обученную модель (или весь Pipeline!) в файл
joblib.dump(model, "my_model.joblib")

# Позже — загрузить и сразу использовать, без переобучения
model = joblib.load("my_model.joblib")
model.predict(X_new)

Полезно знать ℹ️

Сохраняй весь Pipeline целиком, а не только модель! Тогда вся предобработка (масштабирование, кодирование) поедет вместе с моделью, и на новых данных всё сработает одинаково. Это ещё одна причина любить Pipeline из главы 10.

Простой API на FastAPI

Чтобы другие программы могли обращаться к твоей модели, её оборачивают в API — программный интерфейс. FastAPI позволяет сделать это компактно. (В курсе для интерфейса мы использовали Gradio — он проще; FastAPI нужен, когда к модели обращается не человек, а другая программа.)

# pip install fastapi uvicorn
from fastapi import FastAPI
import joblib

app = FastAPI()
model = joblib.load("my_model.joblib")

@app.post("/predict")
def predict(features: list[float]):
    prediction = model.predict([features])[0]
    return {"prediction": int(prediction)}

# Запуск: uvicorn main:app
# Теперь другие программы могут слать данные и получать прогноз

Дрейф данных (data drift)

Аналогия: модель стареет 💡

Модель обучена на данных прошлого. Но мир меняется: вкусы, цены, поведение людей. Со временем новые данные всё меньше похожи на те, на которых модель училась, — это дрейф данных (data drift). Модель «стареет» и предсказывает всё хуже, хотя её код не менялся. Как карта города, которая устаревает по мере стройки новых улиц.

Что с этим делать: периодически сравнивать распределение свежих данных с обучающими (не «уехало» ли среднее, не появились ли новые категории) и следить за метриками на свежих данных. Если качество падает — модель пора переобучить на новых данных. В серьёзных системах это делают автоматически и регулярно.

Жизненный цикл модели

ЭтапЧто происходит
ОбучениеМодель учится на исторических данных
СохранениеМодель (Pipeline) сохраняется в файл
РазвёртываниеМодель доступна через API или приложение
МониторингСледим за качеством и дрейфом данных
ПереобучениеПри падении качества — учим заново на свежих данных

Этот цикл повторяется: модель — не «сделал и забыл», а живая система, которую поддерживают. Понимание этого отличает учебный проект от промышленного.
