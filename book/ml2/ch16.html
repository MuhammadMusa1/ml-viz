Глава 16. Семантический поиск и векторные базы

Цель главы 🎯

После этой главы ты сможешь объяснить, чем семантический поиск лучше поиска по ключевым словам, построить простой поиск на эмбеддингах и понимать, зачем нужны векторные базы данных.

Вот где эмбеддинги показывают силу. Обычный поиск ищет совпадение слов. Семантический поиск ищет по смыслу — находит нужное, даже если ты спросил другими словами. Это сердце RAG и умных ассистентов, которые мы соберём в следующей фазе.

Аналогия: библиотекарь vs указатель 💡

Поиск по ключевым словам — как алфавитный указатель в конце книги: ищет точное слово, а синоним не найдёт. Семантический поиск — как опытный библиотекарь: ты говоришь «мне про то, как чинить велосипед», а он приносит книгу «ремонт двухколёсного транспорта», хотя слова другие. Он понял смысл запроса, а не сверял буквы. В этом вся разница.

Как работает семантический поиск

Идея в три шага: (1) заранее превращаем все документы в эмбеддинги и храним; (2) запрос пользователя тоже превращаем в эмбеддинг; (3) находим документы, чьи векторы ближе всего к вектору запроса (косинусная близость из главы 13). Ближе по смыслу — выше в результатах. Никаких точных слов не требуется.

from sentence_transformers import SentenceTransformer, util

model = SentenceTransformer("all-MiniLM-L6-v2")

# База знаний (представь — сотни абзацев)
docs = [
    "Как заменить цепь на велосипеде",
    "Рецепт домашней пиццы",
    "Настройка тормозов двухколёсного транспорта",
    "Уход за комнатными растениями",
]
doc_emb = model.encode(docs)          # заранее кодируем все документы

# Запрос ДРУГИМИ словами, чем в документах
query = "починить велик"
q_emb = model.encode(query)

# Находим самый близкий по смыслу документ
scores = util.cos_sim(q_emb, doc_emb)[0]
best = scores.argmax()
print("Нашлось:", docs[best])   # найдёт про цепь/тормоза, не про пиццу

Запрос «починить велик» найдёт документы про велосипед, хотя таких слов в них нет.

Зачем нужны векторные базы

Аналогия: от блокнота к каталогу 💡

Пока документов десятки — можно сравнивать запрос со всеми подряд, как в примере. Но когда их миллионы, перебирать каждый — слишком медленно. Векторная база данных (Chroma, FAISS, Pinecone) — это умный каталог, который хранит миллионы векторов и находит ближайшие за миллисекунды, не сравнивая со всеми подряд. Как каталог в огромной библиотеке против перебора всех полок вручную.

# pip install chromadb
import chromadb

client = chromadb.Client()
collection = client.create_collection("my_docs")

# Добавляем документы — Chroma сама посчитает эмбеддинги и сохранит
collection.add(documents=docs, ids=[str(i) for i in range(len(docs))])

# Поиск по смыслу — одной командой
result = collection.query(query_texts=["починить велик"], n_results=2)
print(result["documents"])

Полезно знать ℹ️

Векторная база берёт на себя всё: считает эмбеддинги, хранит их, быстро находит ближайшие. Для учебных проектов Chroma удобнее всего — работает локально, ставится одной командой, не требует сервера. Именно связку «эмбеддинги + векторная база» мы используем в следующей фазе как основу RAG.

Задания

Базовый путь 🟢

Собери семантический поиск по 8–10 своим коротким текстам (заметки, факты, вопросы). Задай запрос ДРУГИМИ словами, чем в текстах, и проверь, что находится нужное по смыслу. Сравни с обычным поиском по слову (find/in).

Продвинутый путь 🔵

Загрузи в Chroma 50+ абзацев (например, из статьи или учебника) и построй поиск с выдачей топ-3 результатов. Придумай 5 запросов-перефразировок и оцени, насколько релевантна выдача. Где поиск ошибается и почему?
