Глава 26. Приватно и офлайн: локальные модели и LoRA

Цель главы 🎯

После этой главы ты сможешь запустить LLM локально через Ollama, объяснить, когда это лучше облака, и понимать идею эффективного дообучения LoRA/QLoRA (обзорно).

До сих пор мы часто обращались к моделям по сети. Но LLM можно запускать прямо на своём компьютере — это важно для приватности, работы без интернета и экономии. А ещё такие модели можно дообучать под себя дёшево — через LoRA. Разберём оба, второе — обзорно.

Локальные модели: Ollama

Аналогия: своя кухня против ресторана 💡

Облачная LLM (по API) — как ресторан: качественно, но платно, и нужно «доехать» (интернет), а твой заказ видит кухня ресторана. Локальная модель через Ollama — как готовить у себя дома: бесплатно, работает без интернета, и никто не видит твоих данных. Домашняя еда попроще ресторанной (локальные модели слабее гигантов), зато приватно, всегда доступно и без счёта. Для чувствительных данных и школ без стабильного интернета — незаменимо.

# Ollama ставится отдельно (ollama.com), затем модель тянется одной командой:
# ollama pull llama3

import ollama

response = ollama.chat(model="llama3", messages=[
    {"role": "user", "content": "Объясни, что такое эмбеддинг"},
])
print(response["message"]["content"])
# Всё считается локально — данные не уходят в интернет

Мы уже использовали Ollama в RAG (глава 20) как локальную LLM. Это тот же инструмент. Локальные модели бывают разного размера: маленькие бегают даже на ноутбуке, большие требуют мощной видеокарты. Для приватных данных (медицина, финансы, персональная информация) локальный запуск часто не роскошь, а требование.

Когда локально, когда облако

СитуацияВыбор
Приватные / секретные данныеЛокально (данные не покидают компьютер)
Нет стабильного интернетаЛокально
Нужно максимальное качествоОблако (большие модели мощнее)
Много запросов, экономияЛокально (нет оплаты за каждый вызов)
Нет мощного железаОблако (или маленькая локальная модель)

LoRA/QLoRA: дообучение без 100 видеокарт (обзорно)

Аналогия: стикеры-заметки вместо переписывания книги 💡

Дообучить огромную LLM целиком — как переписать всю книгу ради нескольких правок: нужны сотни видеокарт и огромные деньги. LoRA (Low-Rank Adaptation) делает умнее: замораживает всю модель и добавляет маленькие «стикеры-заметки» — крошечные обучаемые довески к слоям. Учатся только они (доли процента от размера модели), а основная модель не трогается. QLoRA идёт дальше — сжимает модель (квантование), чтобы всё влезло даже на одну бесплатную видеокарту Colab. Так дообучение LLM становится доступным школьнику, а не только корпорации.

Идея в двух словах: не трогаем гигантскую модель, обучаем маленькие добавки. Результат — «адаптер» весом в мегабайты, который подключается к базовой модели и специализирует её под твою задачу (свой стиль, своя область). Это стандартный сегодня способ дообучать LLM на скромном железе. Глубоко мы в это не ныряем — важно знать, что это существует и что дообучение LLM реально без суперкомпьютера.

Полезно знать ℹ️

Связь с фазой 1: LoRA — это разновидность fine-tuning (глава 18 фазы 3), только для огромных LLM и очень экономная. Инструменты: библиотека PEFT от Hugging Face + bitsandbytes для квантования. Для учебных целей достаточно понимать идею «замораживаем модель, учим маленькие адаптеры». Практическое дообучение LLM — тема для отдельного глубокого погружения, когда будешь готов.

Задания

Базовый путь 🟢

Установи Ollama, скачай небольшую модель (например, llama3 или phi3) и пообщайся с ней локально. Задай те же вопросы облачной модели (если есть доступ). Сравни качество и скорость. Для каких задач локальной модели уже достаточно?

Продвинутый путь 🔵

Собери свой RAG из главы 20 полностью на локальных моделях (Ollama + локальные эмбеддинги) — без единого обращения в интернет. Убедись, что всё работает офлайн. Затем изучи по документации PEFT идею LoRA-дообучения и опиши своими словами, что и зачем там замораживается.
