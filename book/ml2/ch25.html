Глава 25. Команда ботов: мульти-агентные системы

Цель главы 🎯

После этой главы ты сможешь объяснить, что такое AI-агент и мульти-агентная система, и описать, как несколько специализированных агентов решают задачу вместе (на уровне идеи и простой схемы).

Топ-тема 2025–2026 годов. Один агент с инструментами (глава 24) — мощно. Но сложные задачи решают команды агентов, каждый со своей ролью, которые общаются между собой. Разберём идею: это следующий уровень, к которому ты уже готов.

Аналогия: редакция журнала 💡

Представь, как делают статью в журнале. Один человек мог бы всё сам, но команда справляется лучше: исследователь собирает факты, автор пишет черновик, редактор правит, корректор проверяет ошибки. Каждый — специалист в своём. Мульти-агентная система устроена так же: несколько LLM-агентов с разными ролями (и своими инструментами) передают работу друг другу. Разделение труда работает и для ботов.

Агент против чат-бота (напоминание)

Из тома 1: чат-бот только разговаривает, агент — действует (использует инструменты, из главы 24). Мульти-агентная система — это несколько таких агентов, которые не просто действуют, но и координируются: передают друг другу промежуточные результаты, спорят, проверяют работу друг друга.

Типичные роли в команде агентов

Агент-рольЧто делает
ПланировщикРазбивает большую задачу на подзадачи, раздаёт исполнителям
ИсследовательИщет информацию (веб-поиск, RAG, базы)
ИсполнительДелает конкретную работу (пишет код, текст, считает)
Критик / проверяющийПроверяет результат, находит ошибки, отправляет на доработку

Как они общаются

Аналогия: эстафета с проверкой 💡

Работа идёт как эстафета, но с контролем качества. Планировщик разбивает задачу и передаёт исследователю; тот собирает данные и передаёт исполнителю; исполнитель делает черновик и отдаёт критику; критик находит изъян — возвращает исполнителю на доработку; когда критик доволен — задача готова. Этот цикл «сделал → проверили → доработал» и даёт мульти-агентным системам их силу: они сами ловят и исправляют свои ошибки.

# Идея мульти-агентной системы (псевдокод для понимания)
# Реальные фреймворки: CrewAI, AutoGen, LangGraph

planner = Agent(role="Планировщик", goal="разбить задачу на шаги")
researcher = Agent(role="Исследователь", tools=[search, rag])
writer = Agent(role="Автор", goal="написать текст по данным")
critic = Agent(role="Критик", goal="найти ошибки и улучшить")

# Агенты передают работу по цепочке с проверкой
task = "Подготовить обзор про ИИ в медицине"
plan = planner.run(task)
data = researcher.run(plan)
draft = writer.run(data)
final = critic.review(draft)   # вернёт на доработку или утвердит

Внимание: не усложняй раньше времени ⚠️

Мульти-агенты — мощно и модно, но это НЕ всегда нужно. Для большинства задач хватает одного агента с инструментами (глава 24) или простого RAG. Несколько агентов добавляют сложность, стоимость (каждый агент — вызовы LLM) и новые точки отказа. Бери мульти-агентную систему, только когда задача реально распадается на разные роли и одиночный агент не справляется. Простое решение, которое работает, лучше сложного, которое красиво звучит.

Задания

Базовый путь 🟢

Спроектируй (на бумаге, без кода) мульти-агентную систему для задачи «подготовить доклад по теме»: какие роли-агенты нужны, что делает каждый, как они передают работу и кто проверяет результат. Нарисуй схему стрелками.

Продвинутый путь 🔵

Собери простую систему из двух агентов на любом фреймворке (или вручную через два вызова LLM с разными системными промптами): «автор» пишет черновик, «критик» его улучшает. Сравни финальный результат с ответом одного агента. Стало ли лучше? Оправдана ли сложность?

Вопросы для обсуждения 💬

  1. Чем мульти-агентная система отличается от одного агента с инструментами?
  2. Почему цикл «сделал → проверил критик → доработал» повышает качество?
  3. Когда мульти-агенты оправданы, а когда это лишнее усложнение?
