Глава 4. GPU, кривые обучения, Dropout и BatchNorm

Цель главы 🎯

После этой главы ты сможешь перенести обучение на GPU, читать кривые обучения (train vs validation) и применять Dropout и BatchNorm для борьбы с переобучением и ускорения обучения.

Модель обучается, но медленно, и склонна переобучаться. В этой главе три инструмента, которые превращают учебную сеть в рабочую: GPU (скорость), кривые обучения (диагностика) и регуляризация Dropout/BatchNorm (качество).

GPU: ускорение в десятки раз

Аналогия: один математик или тысяча 💡

Обычный процессор (CPU) — как один гениальный математик: решает задачи по очереди, очень умно. GPU — как тысяча школьников, каждый считает простую арифметику, но все одновременно. Обучение сети — это миллионы простых операций над числами, и «тысяча параллельно» бьёт «одного умного» в десятки раз. Поэтому глубокие сети учат на GPU. В Colab он бесплатный: Среда выполнения → сменить на GPU.

# --- Мини-настройка: глава запускается сама (данные и сеть из глав 2-3) ---
import torch, torch.nn as nn
from torchvision import datasets, transforms
from torch.utils.data import DataLoader
_ds = datasets.MNIST(root="data", train=True, download=True,
                     transform=transforms.ToTensor())
train_loader = DataLoader(_ds, batch_size=64, shuffle=True)
class Net(nn.Module):                       # та же сеть, что в главе 3
    def __init__(self):
        super().__init__()
        self.flatten = nn.Flatten()
        self.fc1 = nn.Linear(28*28, 128)
        self.fc2 = nn.Linear(128, 10)
        self.relu = nn.ReLU()
    def forward(self, x):
        x = self.flatten(x)
        x = self.relu(self.fc1(x))
        return self.fc2(x)
# --- конец мини-настройки ---

# Определяем устройство: GPU если есть, иначе CPU
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
print("Устройство:", device)

model = Net().to(device)            # переносим модель на GPU

# В цикле обучения переносим и данные:
for images, labels in train_loader:
    images, labels = images.to(device), labels.to(device)
    # ... дальше обычный цикл обучения

Внимание, частая ошибка ⚠️

И модель, и данные должны быть на одном устройстве. Если модель на GPU (.to(device)), а данные забыл перенести — получишь ошибку "Expected all tensors to be on the same device". Правило: перенёс модель — переноси и каждый батч данных в цикле. Это самая частая ошибка при переходе на GPU.

Кривые обучения: train против validation

В томе 1 мы диагностировали переобучение по разнице train/test. В PyTorch это делают наглядно — рисуют кривые обучения: как падает ошибка на обучающих и на проверочных данных по эпохам. Форма кривых сразу говорит, что не так.

Для этого данные делят на три части (а не две, как раньше): train (учимся), validation (следим за обучением и настраиваем), test (финальная честная проверка, один раз в конце). Validation — это «репетиция экзамена», test — «сам экзамен».

Как читать кривые обучения ℹ️

Обе кривые падают и сближаются — отлично, модель учится и обобщает.

Train падает, а validation растёт (расходятся) — переобучение: сеть зубрит train. Пора Dropout / early stopping.

Обе застряли высоко — недообучение: сеть слишком проста или мало училась. Усложни модель или учи дольше.

Кривая validation скачет — слишком большой learning rate или маленький батч.

Dropout: случайно «отключаем» нейроны

Аналогия: команда без незаменимых 💡

Dropout во время обучения случайно «выключает» часть нейронов на каждом шаге. Зачем? Чтобы сеть не полагалась на отдельные нейроны, а распределяла знание — как в команде, где нет незаменимых людей и любой может подстраховать. В результате сеть устойчивее и меньше переобучается. На проверке (eval) Dropout автоматически выключается — работают все нейроны.

BatchNorm: держим числа в узде

BatchNorm (батч-нормализация) нормирует значения внутри сети между слоями, не давая им «разбегаться» в слишком большие или малые. Это ускоряет и стабилизирует обучение — сеть учится быстрее и надёжнее. Добавляется как обычный слой.

class BetterNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(28*28, 256)
        self.bn1 = nn.BatchNorm1d(256)      # нормализация
        self.drop = nn.Dropout(0.3)         # выключаем 30% нейронов
        self.fc2 = nn.Linear(256, 10)
        self.relu = nn.ReLU()

    def forward(self, x):
        x = x.flatten(1)
        x = self.relu(self.bn1(self.fc1(x)))
        x = self.drop(x)                    # dropout после активации
        return self.fc2(x)

Эти два слоя — Dropout и BatchNorm — почти всегда улучшают глубокие сети. Именно поэтому важны model.train() и model.eval() из прошлой главы: они включают и выключают эти слои в нужный момент.
