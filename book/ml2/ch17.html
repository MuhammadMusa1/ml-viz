Глава 17. Точнее ранжирование: кросс-энкодеры

Цель главы 🎯

После этой главы ты сможешь объяснить разницу между би-энкодером и кросс-энкодером и применять кросс-энкодер для переранжирования результатов поиска (кратко, на уровне идеи и готового кода).

Семантический поиск из прошлой главы быстр, но не идеально точен. Есть приём поднять качество на следующий уровень — кросс-энкодеры. Разберём идею кратко: это «следующий уровень» после того, что ты уже умеешь, и важная часть хороших поисковых и RAG-систем.

Аналогия: быстрый отбор и внимательное собеседование 💡

Представь наём сотрудника. Би-энкодер (обычные эмбеддинги из главы 14) — как быстрый просмотр тысяч резюме по ключевым признакам: мгновенно, но грубо. Кросс-энкодер — как вдумчивое собеседование, где запрос и документ рассматривают ВМЕСТЕ, сравнивая напрямую: гораздо точнее, но долго и по одному. Нельзя собеседовать тысячу человек, но можно топ-20 после быстрого отбора.

Разница в одном образе

Би-энкодерКросс-энкодер
Как работаетКодирует запрос и документ по отдельности, потом сравнивает векторыСмотрит на пару «запрос + документ» вместе и оценивает соответствие
СкоростьОчень быстро (векторы считаются заранее)Медленно (нужно прогонять каждую пару)
ТочностьХорошаяВыше
КогдаПервичный поиск среди тысяч/миллионовПереранжировать топ-N кандидатов

Связка на практике: retrieve → rerank

Профессиональный приём — двухэтапный поиск: сначала быстрый би-энкодер достаёт топ-20 кандидатов из миллионов (retrieve), затем медленный, но точный кросс-энкодер переранжирует эти 20 и поднимает лучшие наверх (rerank). Быстро И точно одновременно.

from sentence_transformers import CrossEncoder

# Кросс-энкодер для переранжирования
reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")

query = "как починить велосипед"
# кандидаты, которые уже нашёл быстрый семантический поиск (глава 16)
candidates = [
    "Настройка тормозов двухколёсного транспорта",
    "Рецепт домашней пиццы",
    "Как заменить цепь на велосипеде",
]

# Оцениваем пары "запрос + кандидат" вместе
pairs = [(query, c) for c in candidates]
scores = reranker.predict(pairs)

# Сортируем кандидатов по оценке кросс-энкодера
ranked = sorted(zip(scores, candidates), reverse=True)
for score, text in ranked:
    print(f"{score:.2f}  {text}")

Кросс-энкодер точнее расставит велосипедные документы выше, а пиццу — вниз.

Когда это нужно (а когда нет) ℹ️

Кросс-энкодер стоит добавлять, когда качество поиска критично (юридические документы, медицина, серьёзный RAG) и когда кандидатов уже немного (топ-10..50 после первичного поиска). Для простого проекта или прототипа хватает одного би-энкодера из главы 16 — не усложняй раньше времени. Это инструмент «когда нужно ещё точнее», а не обязательный шаг.

Задания

Базовый путь 🟢

Возьми топ-5 результатов своего семантического поиска из главы 16 и переранжируй их кросс-энкодером. Изменился ли порядок? Стал ли он лучше на твой взгляд?

Продвинутый путь 🔵

Построй полную связку retrieve → rerank: би-энкодер достаёт топ-10 из 50+ документов, кросс-энкодер переранжирует их в топ-3. Сравни качество топ-3 «только би-энкодер» vs «би-энкодер + rerank» на нескольких запросах.
