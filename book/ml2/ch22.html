Глава 22. Живой ответ: streaming

Цель главы 🎯

После этой главы ты сможешь объяснить, зачем ответ LLM выдают построчно (streaming), и включить потоковую выдачу, чтобы интерфейс ощущался быстрым и живым.

Небольшая, но важная деталь, которая отличает «сырой» проект от продукта, приятного в использовании. В ChatGPT ответ печатается по словам, а не появляется целиком после паузы. Это streaming — потоковая выдача. Разберём, зачем это и как включить.

Аналогия: официант, который приносит блюда по мере готовности 💡

Без streaming пользователь смотрит на пустой экран, пока модель целиком не допишет ответ — как если бы официант ждал, пока приготовятся ВСЕ блюда, и принёс их разом через полчаса. Со streaming слова появляются по мере генерации — официант несёт каждое блюдо сразу, как только оно готово. Ответ занимает столько же времени, но ощущается быстрым и живым: видно, что система работает, и можно начать читать сразу.

Почему это важнее, чем кажется

LLM генерирует текст токен за токеном (том 1). Без streaming мы ждём последний токен и показываем всё разом — на длинном ответе это несколько секунд пустого экрана, и кажется, что «завис». Со streaming показываем токены сразу, как они рождаются. Технически быстрее не становится, но пользовательское ощущение меняется кардинально — а в продукте ощущение и есть половина дела.

Streaming в коде

Почти все API и библиотеки поддерживают потоковую выдачу — обычно это флаг stream=True и цикл по кусочкам ответа.

# Пример потоковой выдачи (Ollama; у облачных API — похоже)
import ollama

stream = ollama.chat(
    model="llama3",
    messages=[{"role": "user", "content": "Объясни, что такое RAG"}],
    stream=True,          # <-- включаем потоковую выдачу
)

# Печатаем ответ по кусочкам, как он генерируется
for chunk in stream:
    print(chunk["message"]["content"], end="", flush=True)

Полезно знать ℹ️

В Gradio (том 1) streaming делается через функцию-генератор с yield: вместо return ты yield-ишь всё более длинный ответ, и интерфейс обновляется на глазах. Так собирают чат-ботов, которые «печатают» вживую. Флаг stream=True есть и у облачных API (OpenAI, Anthropic) — принцип везде один: не ждать весь ответ, а отдавать по кусочкам.
