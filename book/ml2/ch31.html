Глава 31. Ускоряем разведку: авто-EDA и работа с датами

Цель главы 🎯

После этой главы ты сможешь за минуты проводить разведку данных через авто-EDA (ydata-profiling) и продвинуто работать с датами и временем, извлекая из них полезные признаки.

В томе 1 разведка данных (EDA) делалась вручную — строчка за строчкой, график за графиком. Это важно уметь. Но в реальной работе есть инструменты, которые делают базовую разведку за минуты, и отдельный навык — работа с датами, которых в реальных данных полно.

Авто-EDA: отчёт по данным одной командой

Аналогия: медосмотр всего организма разом 💡

Ручная EDA — как проверять здоровье по одному анализу: смотришь давление, потом кровь, потом ещё что-то. Авто-EDA (ydata-profiling) — как полный медосмотр разом: одна команда, и ты получаешь отчёт по ВСЕМ столбцам сразу — распределения, пропуски, выбросы, корреляции, дубликаты. За минуту видишь общую картину здоровья данных и понимаешь, куда копать глубже вручную.

# pip install ydata-profiling
from ydata_profiling import ProfileReport
import pandas as pd

df = pd.read_csv("data.csv")

# Один вызов — полный отчёт по всем столбцам
report = ProfileReport(df, title="Разведка данных")
report.to_file("report.html")   # открой в браузере
# В отчёте: типы, пропуски, распределения, корреляции, дубликаты

Внимание: авто-EDA не заменяет мышление ⚠️

Инструмент даёт данные для размышления, но выводы делаешь ты. Он покажет «в столбце 30% пропусков» и «эти два признака коррелируют», но НЕ скажет, что это значит для твоей задачи и что с этим делать. Авто-EDA экономит часы рутины, но понимание данных, поиск утечки, решение, какие признаки создать, — по-прежнему на тебе. Это ускоритель ручной EDA из тома 1, а не замена ей.

Работа с датами: клад полезных признаков

В томе 1 мы касались дат кратко. В реальных данных дата и время встречаются постоянно (заказы, события, логи), и из них можно извлечь массу сильных признаков — часто важнее «сырых» чисел. Это продвинутый feature engineering для времени.

import pandas as pd

df["date"] = pd.to_datetime(df["date"])   # превращаем в настоящую дату

# Извлекаем календарные признаки
df["year"] = df["date"].dt.year
df["month"] = df["date"].dt.month
df["dayofweek"] = df["date"].dt.dayofweek      # 0=пн … 6=вс
df["is_weekend"] = df["dayofweek"].isin([5, 6]).astype(int)
df["hour"] = df["date"].dt.hour                # для времени
df["quarter"] = df["date"].dt.quarter

# Разница между датами (например, возраст заказа в днях)
df["days_since"] = (pd.Timestamp.now() - df["date"]).dt.days

Продвинутые приёмы с датами

Что ещё вытаскивают из времени ℹ️

Циклические признаки: час и месяц цикличны (после 23:00 идёт 0:00, декабрь → январь). Их кодируют через синус/косинус, чтобы модель понимала: 23 час близко к 0, а не «далеко». Приём для продвинутых.

Лаги и окна (из фазы про временные ряды тома 1): значение неделю назад, среднее за 7 дней — сильные признаки для прогнозов.

Праздники и события: флаг «праздничный день», «день зарплаты», «сезон распродаж» — часто объясняют всплески в данных.

Разницы дат: сколько дней между регистрацией и первой покупкой, возраст клиента, срок с последней активности.

Локальный пример: для прогноза продаж в Таджикистане флаги Навруза, Рамадана, начала учебного года объясняют скачки спроса, которые из «сырой» даты модель сама не увидит. Знание своего контекста + правильные признаки из дат = заметный прирост качества.
