Глава 32. Мини-проект: свой датасет с нуля

Цель главы 🎯

После этой главы ты пройдёшь полный путь настоящего проекта: добыть данные (парсинг или SQL), очистить, исследовать (авто-EDA) и обучить на них модель — на данных, которых нет ни в одном учебнике.

Пятая фаза завершается проектом, который отличает настоящего специалиста от того, кто умеет работать только с готовыми датасетами. Ты создашь свой датасет с нуля и обучишь на нём модель. Это ценнее любого проекта на Titanic — потому что таких данных больше ни у кого нет.

Полный путь проекта

Проект объединяет всю фазу 5 и возвращает к навыкам тома 1 (модель, оценка). Пять этапов:

  1. Добыть данные: парсинг сайта (глава 29) ИЛИ выгрузка через SQL/DuckDB (глава 28) ИЛИ свой опрос/сбор.
  2. Очистить: грязные данные из реальности — пропуски, дубликаты, разные форматы (навыки тома 1 + regex).
  3. Исследовать: авто-EDA (глава 31) для общей картины + ручная проверка гипотез.
  4. Признаки: feature engineering, особенно из дат (глава 31), под свою задачу.
  5. Обучить и оценить: модель в Pipeline, baseline, честная метрика (том 1).

Идеи датасетов, которые можно собрать

  • Цены на товары/жильё с сайта объявлений → предсказать цену (регрессия).
  • Данные о матчах любимой команды → предсказать исход (классификация).
  • Свои данные за месяц (сон, учёба, настроение, экранное время) → найти связи.
  • Отзывы/комментарии по теме → классифицировать тональность (мост к фазе 3).
  • Открытые данные (погода, курсы НБТ, статистика) через API → прогноз.

Развилка путей

Базовый путь 🟢

Собери небольшой датасет (100–300 строк) простым способом (опрос, готовый API, простой парсинг), очисти, проведи авто-EDA и обучи модель с baseline. Главное — пройти весь путь целиком.

Продвинутый путь 🔵

Собери датасет парсингом с нескольких страниц (этично!) или сложным SQL-запросом с JOIN. Проведи полный feature engineering (включая признаки из дат), сравни несколько моделей, добейся уверенного превосходства над baseline. Оформи как исследование.

Чек-лист проекта

Проект готов, если 🎯

Данные добыты самостоятельно (не скачаны готовым датасетом).

Описано, откуда и как собраны данные (и что этика парсинга соблюдена).

Данные очищены, есть отчёт авто-EDA.

Созданы осмысленные признаки (в т.ч. из дат, если они есть).

Модель в Pipeline обучена и сравнена с baseline честной метрикой.

Есть README: задача, источник данных, находки, результат.

Главная мысль фазы 5 🎯

Ты научился тому, что отделяет настоящего специалиста от новичка: добывать данные из баз (SQL) и из интернета (парсинг), справляться с их объёмом (polars/dask), быстро исследовать (авто-EDA) и грамотно работать с датами. Теперь ты не ждёшь готовый датасет — ты создаёшь его сам. А данные, которых нет ни у кого другого, — это твоё уникальное преимущество в любом проекте и портфолио.

Задания

Базовый путь 🟢

Собери свой датасет любым способом, пройди все пять этапов и обучи модель. В README честно опиши: откуда данные, как чистил, что нашёл в EDA, какой результат против baseline.

Продвинутый путь 🔵

Собери датасет парсингом или сложным SQL, проведи глубокий feature engineering и сравнение моделей. Заверши мини-исследованием: какие признаки оказались важнее всего и почему? Выложи проект (данные + код + README) на GitHub как часть портфолио.
