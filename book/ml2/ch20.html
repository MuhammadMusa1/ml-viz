Глава 20. RAG в деле: ИИ-ассистент по своим документам

Цель главы 🎯

После этой главы ты сможешь объяснить, из каких частей состоит настоящий RAG, и собрать рабочий RAG-конвейер на LangChain: векторная база из фазы 3 плюс языковая модель.

В томе 1 мы делали RAG вручную: находили кусок текста по ключевому слову и вставляли в промпт. Это объясняло идею. Теперь соберём настоящий RAG — с семантическим поиском по векторной базе (фаза 3) и связкой всех частей через LangChain, библиотеку-конструктор для приложений с LLM.

Напоминание: зачем нужен RAG ℹ️

LLM может уверенно выдумывать факты (галлюцинации из тома 1) и не знает твоих личных документов. RAG (Retrieval-Augmented Generation) решает оба: сначала находит нужные фрагменты в ТВОИХ данных (retrieval), затем даёт их модели как «шпаргалку» для ответа (generation). Модель отвечает по реальному тексту, а не по памяти. Это как экзамен с открытой книгой.

Четыре части настоящего RAG

Аналогия: работа референта 💡

Представь референта, которому дали задание ответить на вопрос по архиву. Он: (1) режет документы на карточки и раскладывает по смыслу — это индексация (chunking + эмбеддинги в векторную базу); (2) по вопросу достаёт нужные карточки — retrieval (семантический поиск из фазы 3); (3) читает найденное и формулирует ответ — generation (работа LLM); (4) всё это склеено в единый рабочий процесс — это и делает LangChain. RAG — это оркестр из знакомых тебе инструментов.

ЧастьЧто делаетОткуда навык
ИндексацияРежет документы и кладёт в векторную базуФаза 3, глава 16
RetrievalНаходит релевантные фрагменты по смыслуФаза 3, семантический поиск
GenerationLLM пишет ответ по найденномуТом 1, работа с LLM
ОркестрацияСвязывает всё в конвейерLangChain (новое)

RAG на LangChain

LangChain соединяет части в несколько шагов. Ниже — минимальный рабочий RAG: загрузили документы, проиндексировали, задали вопрос, получили ответ по своим данным.

# pip install langchain langchain-community chromadb sentence-transformers
from langchain_community.vectorstores import Chroma
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain.chains import RetrievalQA
from langchain_community.llms import Ollama   # локальная LLM

# 1. ИНДЕКСАЦИЯ: режем документ на куски и кладём в векторную базу
text = open("my_docs.txt", encoding="utf-8").read()
chunks = RecursiveCharacterTextSplitter(
    chunk_size=500, chunk_overlap=50).split_text(text)

emb = HuggingFaceEmbeddings(
    model_name="paraphrase-multilingual-MiniLM-L12-v2")
db = Chroma.from_texts(chunks, emb)

# 2+3. RETRIEVAL + GENERATION в одном конвейере
qa = RetrievalQA.from_chain_type(
    llm=Ollama(model="llama3"),          # или облачная LLM
    retriever=db.as_retriever(search_kwargs={"k": 3}))

# Задаём вопрос по СВОИМ документам
print(qa.invoke("Что сказано про сроки?"))

Ожидаемый результат: ответ модели, опирающийся на найденные фрагменты твоих документов.

Разбери код по частям RAG: text_splitter режет текст (индексация), Chroma хранит и ищет (retrieval — прямо из фазы 3), Ollama пишет ответ (generation), а RetrievalQA связывает всё (оркестрация). Каждая часть тебе уже знакома — LangChain лишь соединил их.

Внимание ⚠️

LangChain быстро развивается, и названия импортов иногда меняются между версиями. Если импорт не работает — проверь актуальную документацию под свою версию. Суть при этом остаётся: splitter → embeddings → vectorstore → retriever → LLM → chain. Держись за смысл частей, а не за точные имена.
