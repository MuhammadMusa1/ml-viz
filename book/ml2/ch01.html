Глава 1. Почему PyTorch: тензоры и автоград

Цель главы 🎯

После этой главы ты сможешь объяснить, что такое тензор и чем он похож на массив NumPy, создавать тензоры и выполнять операции, а также объяснить своими словами, что делает автоград (автоматическое дифференцирование).

PyTorch стоит на двух китах: тензоры (данные) и автоград (автоматический расчёт градиентов для обучения). Разберёмся с обоими без сложной математики — на уровне интуиции, которого хватит для всей работы.

Тензор — это массив на стероидах

Аналогия: знакомый NumPy, но умнее 💡

Если ты помнишь массивы NumPy из тома 1 — ты уже почти знаешь тензоры. Тензор PyTorch — это тот же многомерный массив чисел (число, вектор, матрица, картинка), только с двумя суперспособностями: он умеет считаться на GPU (в сотни раз быстрее) и запоминать, как из него получаются другие тензоры, чтобы потом автоматически посчитать градиенты. Всё остальное — как в NumPy.

import torch

# Создаём тензоры — почти как в NumPy
a = torch.tensor([1.0, 2.0, 3.0])
b = torch.tensor([4.0, 5.0, 6.0])

print(a + b)          # tensor([5., 7., 9.])
print(a * 2)          # tensor([2., 4., 6.])
print(a.shape)        # torch.Size([3])

# Матрица нулей/единиц, случайные числа
zeros = torch.zeros(2, 3)
rand = torch.rand(2, 3)     # случайные от 0 до 1

Из NumPy в тензор и обратно — одна строка: torch.tensor(np_array) и tensor.numpy(). Поэтому весь твой опыт из тома 1 (форма, reshape, индексация) переносится сюда напрямую.

Автоград: как машина понимает, куда крутить веса

Вспомни из тома 1: нейросеть учится, подкручивая веса в сторону уменьшения ошибки. Чтобы узнать, в какую сторону крутить каждый вес, нужен градиент — по сути, стрелка «туда, где ошибка растёт быстрее всего» (крутим в противоположную). Раньше это делал Keras незаметно. В PyTorch за это отвечает автоград, и он делает это автоматически.

Аналогия: спуск с горы в тумане 💡

Представь, что стоишь на склоне в густом тумане и хочешь спуститься в низину (минимум ошибки). Ты не видишь всю гору, но можешь пощупать ногой, куда идёт уклон под тобой, и сделать шаг вниз. Градиент — это и есть «уклон под ногами»: направление наибольшего роста. Автоград сам вычисляет этот уклон для каждого веса, а оптимизатор делает шаг вниз. Повторяем — и постепенно спускаемся к минимуму ошибки.

import torch

# requires_grad=True — "следи за этим тензором для градиентов"
x = torch.tensor(2.0, requires_grad=True)

# Некоторая функция ошибки (для примера)
y = x ** 2 + 3 * x          # y = x² + 3x

y.backward()                # автоград считает производную dy/dx

print(x.grad)               # tensor(7.) — уклон в точке x=2
# Проверка вручную: dy/dx = 2x + 3 = 2*2 + 3 = 7 ✓

Ключевой момент: ты написал только формулу вперёд (y из x), а .backward() сам посчитал производную назад. В настоящей сети таких весов миллионы, и автоград считает градиент для каждого одной командой. Это и есть та «магия», которую Keras прятал, — теперь она у тебя в руках.

Внимание, частая ошибка ⚠️

Градиенты в PyTorch накапливаются (складываются) при каждом .backward(). Поэтому перед новым шагом обучения их обязательно обнуляют через optimizer.zero_grad() — иначе градиенты со старых шагов сложатся с новыми, и обучение сломается. Это та самая первая строка цикла обучения из «моста». Забыть zero_grad() — классическая ошибка новичка в PyTorch.

Продвинутый путь 🔵
