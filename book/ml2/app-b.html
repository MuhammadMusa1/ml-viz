Приложение B. Шпаргалка по LangChain и RAG

Сборка RAG из фазы 4: индексация → поиск → генерация. Имена импортов в LangChain меняются между версиями — сверяйся с документацией, держись за смысл шагов.

Части RAG

ЧастьИнструментЧто делает
НарезкаTextSplitterРежет документы на куски (chunks)
ЭмбеддингиHuggingFaceEmbeddingsКуски → векторы смысла
ХранилищеChroma / FAISSВекторная база, быстрый поиск
ПоискretrieverНаходит релевантные куски по вопросу
ГенерацияLLM (Ollama/облако)Пишет ответ по найденному
ОркестрацияRetrievalQA / chainСвязывает всё вместе

Минимальный RAG

from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain_community.vectorstores import Chroma
from langchain.chains import RetrievalQA
from langchain_community.llms import Ollama

# 1. Нарезка
chunks = RecursiveCharacterTextSplitter(
    chunk_size=500, chunk_overlap=50).split_text(text)
# 2. Индексация в векторную базу
emb = HuggingFaceEmbeddings(
    model_name="paraphrase-multilingual-MiniLM-L12-v2")
db = Chroma.from_texts(chunks, emb)
# 3. RAG-конвейер
qa = RetrievalQA.from_chain_type(
    llm=Ollama(model="llama3"),
    retriever=db.as_retriever(search_kwargs={"k": 3}))
print(qa.invoke("вопрос по документам"))

Параметры, которые крутят

КодЧто делает
chunk_sizeРазмер куска (200–1000). Мелко — нет контекста
chunk_overlapПерекрытие (~10%). Чтобы мысль не рвалась
k (в retriever)Сколько кусков достать (обычно 3–5)
embedding modelМногоязычная — для русского
stream=TrueПотоковая выдача ответа

Если RAG отвечает плохо ⚠️

Сначала проверь retrieval: находятся ли нужные куски? (виноват часто он, а не LLM).

Покрути chunking: открой куски глазами — законченные ли это мысли?

Проверь эмбеддинг-модель: многоязычная ли для русских текстов?

Оцени faithfulness: опирается ли ответ на найденное или выдумывает?
