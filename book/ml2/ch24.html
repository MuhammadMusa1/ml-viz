Глава 24. Руки для модели: инструменты и function calling

Цель главы 🎯

После этой главы ты сможешь объяснить, что такое function calling, и дать LLM внешние инструменты (калькулятор, поиск, свою функцию), которые она вызывает сама, когда нужно.

В томе 1 мы собрали крошечного агента «на пальцах». Теперь разберём, как это устроено по-настоящему: LLM может сама решать, что ей нужен внешний инструмент, вызывать его и использовать результат. Это function calling — мост между «моделью, которая говорит» и «моделью, которая действует».

Аналогия: умный, но честный помощник 💡

LLM много знает, но кое-что делает плохо: точно считать (она не калькулятор), знать сегодняшнюю погоду или курс валют (её знания устарели на момент обучения), заглядывать в твою базу данных. Function calling — это когда модель честно признаёт «тут мне нужен инструмент» и просит его вызвать, вместо того чтобы выдумывать ответ. Как умный помощник, который не гадает про погоду, а смотрит в приложение.

Как это работает: три шага

Ты описываешь модели доступные инструменты (что делают, какие аргументы). Дальше цикл: (1) модель, получив вопрос, решает — ответить самой или вызвать инструмент; (2) если инструмент — она возвращает его имя и аргументы, твой код исполняет функцию; (3) результат отдаётся модели, и она формулирует финальный ответ. Модель не исполняет код сама — она лишь говорит, ЧТО вызвать; исполняешь ты.

# Идея function calling (упрощённо). Точный формат — в документации API.

def get_weather(city):
    # тут реальный вызов погодного API
    return f"В городе {city}: +18°C, ясно"

# Описываем инструмент для модели
tools = [{
    "name": "get_weather",
    "description": "Узнать текущую погоду в городе",
    "parameters": {"city": "название города"},
}]

# 1. Модель решает, нужен ли инструмент
response = llm_with_tools("Какая погода в Душанбе?", tools=tools)

# 2. Если модель попросила вызвать инструмент — исполняем
if response.tool_call:
    result = get_weather(**response.tool_call.args)  # мы вызываем
    # 3. Отдаём результат модели для финального ответа
    final = llm_with_tools(tool_result=result)
    print(final)   # "В Душанбе сейчас +18°C и ясно"

Внимание, безопасность ⚠️

Модель говорит, ЧТО вызвать, но решаешь и исполняешь ты. Никогда не давай модели напрямую выполнять опасные действия (удалять файлы, тратить деньги, слать письма) без твоей проверки. Это как в томе 1 с eval() в калькуляторе: в учебном примере ок, в реальном продукте — валидируй аргументы и ограничивай, что инструмент может сделать. Инструмент с «руками» требует ответственности.

Какие инструменты дают моделям

  • Калькулятор — точные вычисления (LLM в арифметике ненадёжна).
  • Поиск в интернете — свежая информация после даты обучения модели.
  • Доступ к базе данных / API — узнать реальные данные (заказы, погода, курсы).
  • Запуск кода — посчитать, построить график, обработать данные.
  • Твой RAG — поиск по документам тоже можно оформить как инструмент.

Задания

Базовый путь 🟢

Дай модели один инструмент — калькулятор (как в томе 1, но через function calling). Задай задачу с точным расчётом и проверь: вызвала ли модель инструмент вместо того, чтобы гадать? Сравни с ответом без инструмента.

Продвинутый путь 🔵

Дай модели два инструмента (например, калькулятор и «поиск факта» из словаря) и задай вопросы, требующие то одного, то другого, то ответа без инструментов. Правильно ли модель выбирает? Оформи свой RAG из главы 20 как инструмент, который модель вызывает при вопросах о документах.
