Глава 39. Финальный командный проект: от данных до деплоя

Цель главы 🎯

После этой главы твоя команда пройдёт полный путь реального ML-продукта — от данных до развёрнутого приложения — с распределением ролей, и защитит его.

Вершина всего тома 2. В томе 1 финальный проект был индивидуальным. Здесь — командный, потому что реальный ML делают командами. Вы объедините ВСЁ: данные (фаза 5), модель (фазы 1–3), возможно LLM (фаза 4) и инженерию (фаза 6). И научитесь главному навыку, которого не даёт никакой код в одиночку, — работать вместе.

Роли в команде

Аналогия: команда, а не солисты 💡

Реальный ML-продукт — как фильм: его не снимает один человек. Нужны разные специалисты, и результат рождается из их слаженной работы. В вашей команде — четыре роли (в маленькой команде один человек может совмещать две). Каждый отвечает за свою часть, но все понимают общую картину. Умение договориться, разделить работу и собрать её воедино — это и есть то, что проверяет финальный проект наравне с техникой.

РольЗа что отвечаетНавыки из тома
Data EngineerДобыть, очистить, подготовить данныеФаза 5
ML EngineerОбучить, оценить, улучшить модельФазы 1–3, том 1
BackendAPI, Docker, деплой, мониторингФаза 6
FrontendИнтерфейс для пользователя (Gradio/веб)Том 1

Что должен содержать проект

Финальный проект — это полноценный ML-продукт, проходящий весь путь. Обязательные части (объединяют весь курс):

  1. Данные: добыты и очищены самостоятельно (SQL/парсинг/сбор из фазы 5), не готовый датасет.
  2. Модель: обучена, с baseline и честной метрикой, в Pipeline (том 1 + фазы 1–3).
  3. Инженерия: модель за API (FastAPI) ИЛИ в Docker, с базовыми тестами (фаза 6).
  4. Интерфейс: приложение, которым можно пользоваться (Gradio/веб), публичная ссылка.
  5. Командная работа: Git с ветками и PR, вклад каждого виден в истории (глава 33).
  6. README и защита: описание продукта, ролей, находок; устная защита командой.

Идеи командных проектов

  • Умный помощник по школьным материалам (RAG из фазы 4 + свой датасет конспектов).
  • Сервис предсказания цен (парсинг объявлений → модель → веб-приложение).
  • Классификатор/детектор на фото (фаза 2) как веб-сервис с API.
  • Анализатор отзывов/комментариев (сбор данных + NLP из фазы 3 + интерфейс).
  • Дашборд с прогнозом (данные через API → модель → визуализация).

Как оценивается командный проект

Оценка складывается из двух частей: командной (общий результат) и индивидуальной (личный вклад, видимый в Git). Это честно: команда отвечает за продукт, но и каждый — за свою роль.

КритерийЧто оценивается
Полнота пути (0–4)Данные → модель → инженерия → интерфейс — весь цикл
Качество модели (0–3)Baseline, метрика, Pipeline, честная оценка
Инженерия (0–3)API/Docker, тесты, воспроизводимость
Командная работа (0–3)Git с ветками/PR, виден вклад каждого
Защита и README (0–3)Ясность рассказа, документация, ответы на вопросы
Личный вклад (0–4)Индивидуально: что сделал конкретный участник

Совет команде 🎯

Начните с малого работающего продукта (как «скелет» в томе 1), потом улучшайте — не пытайтесь сразу сделать идеально. Договоритесь о ролях и ветках в первый день. Общайтесь: половина провалов командных проектов — не от слабого кода, а от «я думал, это делаешь ты». Маленький, но законченный и слаженно сделанный продукт лучше амбициозного, но разваленного.

Главная мысль фазы 6 и всего тома 2 🎯

Ты прошёл путь от «обучил модель в блокноте» до «команда выпустила надёжный ML-продукт»: Git и совместная работа, Docker, API с мониторингом, MLflow, тесты и CI/CD. И собрал всё в командном проекте — так, как это делают в настоящих компаниях. Ты больше не просто умеешь обучать модели — ты умеешь доводить их до продукта и работать в команде. Это и есть разница между учеником и инженером.

Задания

Базовый путь 🟢

Командой (2–4 человека) сделайте проект по чек-листу: свои данные, модель с baseline, интерфейс с публичной ссылкой, Git с ветками и PR, README с ролями. Защитите командой: каждый рассказывает свою часть.

Продвинутый путь 🔵

Доведите проект до полного MLOps-цикла: модель за API в Docker, базовые тесты pytest, эксперименты в MLflow, при возможности CI/CD. Продумайте мониторинг. На защите покажите не только продукт, но и инженерную кухню: как обеспечили надёжность и воспроизводимость.

Вопросы для обсуждения 💬

  1. Почему реальный ML-продукт делают командой, а не в одиночку?
  2. Как навыки всех фаз тома 2 (и тома 1) соединились в вашем проекте?
  3. Что оказалось труднее — техническая часть или командная работа? Почему?
