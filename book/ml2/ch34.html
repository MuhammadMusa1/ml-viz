Глава 34. «Работает у всех»: Docker для ML

Цель главы 🎯

После этой главы ты сможешь объяснить, какую проблему решает Docker, прочитать простой Dockerfile и собрать образ, в котором твоё ML-приложение работает одинаково везде.

Знаменитая беда программистов: «у меня на компьютере работает, а у тебя — нет». Разные версии Python, библиотек, операционных систем — и код ломается при переносе. Docker решает эту проблему раз и навсегда. Это стандарт доставки приложений в реальной работе.

Аналогия: контейнер для перевозки 💡

До морских контейнеров грузы паковали как попало — то не влезало, то билось при перегрузке. Стандартный контейнер изменил всё: что бы внутри ни лежало, снаружи он одинаков и стыкуется с любым кораблём и краном. Docker — то же для программ: он упаковывает твоё приложение ВМЕСТЕ со всем окружением (Python, библиотеки, настройки) в стандартный «контейнер». Этот контейнер запускается одинаково на твоём ноутбуке, на сервере коллеги и в облаке. «Работает у меня» становится «работает у всех».

Dockerfile: рецепт окружения

Dockerfile — текстовый файл с инструкциями: с какой базы начать, что установить, какой код скопировать, чем запустить. Для ML-приложения он выглядит просто.

# Dockerfile для ML-приложения

# 1. Берём готовую базу с Python
FROM python:3.11-slim

# 2. Рабочая папка внутри контейнера
WORKDIR /app

# 3. Ставим зависимости (сначала только их — для кэша)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 4. Копируем свой код
COPY . .

# 5. Команда запуска (например, наш FastAPI из главы 35)
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
# Собрать образ по рецепту и запустить контейнер (в терминале):
docker build -t my-ml-app .          # собрать образ
docker run -p 8000:8000 my-ml-app    # запустить контейнер

Внимание: где это запускать ⚠️

Docker ставится на компьютер отдельно (Docker Desktop) и работает в терминале, а не в Colab. Для школ без такой возможности эту главу можно пройти «на понимание»: важно осознать, ЗАЧЕМ нужен Docker и как читать Dockerfile, даже если запустить негде. Многие облачные платформы (в т.ч. Hugging Face Spaces) умеют собирать Docker сами — тебе нужно лишь положить Dockerfile.

Почему это критично для ML

ML-приложения особенно капризны к окружению: конкретные версии PyTorch, CUDA для GPU, десятки библиотек. Одна несовпадающая версия — и модель не грузится или выдаёт другой результат. Docker фиксирует всё это в образе, гарантируя воспроизводимость: коллега, сервер и облако получают ровно то же окружение, что у тебя. Без Docker командная ML-разработка превращается в бесконечную борьбу с окружением.

Задания

Базовый путь 🟢

Напиши Dockerfile для простого Python-приложения (хотя бы «hello world» или скрипт с pandas). Прочитай его строка за строкой и объясни своими словами, что делает каждая. Если Docker установлен — собери образ и запусти.

Продвинутый путь 🔵

Заверни в Docker своё приложение из прошлых фаз (Gradio или FastAPI): напиши Dockerfile + requirements.txt, собери образ, запусти контейнер и проверь, что приложение доступно. Опиши, какие проблемы с окружением Docker снял.
