Глава 28. SQL для ML без боли: DuckDB

Цель главы 🎯

После этой главы ты сможешь объяснить, зачем ML-специалисту SQL, писать базовые SQL-запросы (SELECT, WHERE, GROUP BY, JOIN) и выполнять их прямо в Python через DuckDB.

В реальных компаниях данные живут не в CSV-файлах, а в базах данных, и достают их языком SQL. Это один из самых востребованных навыков ML-специалиста. Хорошая новость: с DuckDB можно писать SQL прямо в Python, без установки тяжёлой базы, — учиться легко и приятно.

Аналогия: заказ официанту вместо похода на кухню 💡

Представь огромный склад данных. Можно самому бегать по полкам и всё перебирать (так делает pandas, загружая всё в память). А можно дать точный заказ кладовщику: «принеси только красные коробки с полки 3, отсортированные по весу» — и он вернёт ровно нужное. SQL — это язык таких заказов к данным: ты описываешь ЧТО хочешь получить, а база сама эффективно это достаёт. Для больших данных это куда быстрее, чем тащить всё к себе.

DuckDB: SQL прямо в Python

DuckDB — лёгкая база, которая живёт внутри Python и умеет выполнять SQL прямо по твоим данным (в том числе по DataFrame pandas и по CSV-файлам, не загружая их целиком). Ставится одной командой, сервер поднимать не нужно.

# pip install duckdb
import duckdb
import pandas as pd

df = pd.read_csv("sales.csv")

# SQL прямо по DataFrame — DuckDB видит переменную df
result = duckdb.sql("""
    SELECT city, AVG(price) AS avg_price
    FROM df
    WHERE price > 100
    GROUP BY city
    ORDER BY avg_price DESC
""").df()      # .df() — вернуть результат как pandas DataFrame

print(result)

Ожидаемый результат: таблица средних цен по городам, отсортированная по убыванию.

Четыре кита SQL

SQL огромен, но 90% работы делают четыре конструкции. Освой их — и ты сможешь достать почти любые данные.

КонструкцияЧто делаетАналог в pandas
SELECT ... FROMВыбрать столбцы из таблицыdf[["col1","col2"]]
WHEREОтобрать строки по условиюdf[df["x"] > 5]
GROUP BYСгруппировать и посчитать (AVG, COUNT, SUM)df.groupby(...)
JOINСоединить две таблицы по общему ключуpd.merge(...)

Полезно знать ℹ️

Ты уже знаешь эти операции по pandas из тома 1 — SQL просто выражает их другим языком. SELECT+WHERE — это фильтрация, GROUP BY — это groupby, JOIN — это merge. Поэтому SQL даётся легко тому, кто освоил pandas: те же идеи, другой синтаксис. А JOIN особенно важен: реальные данные почти всегда разбросаны по нескольким таблицам (клиенты в одной, заказы в другой), и их нужно соединять.

JOIN: соединяем таблицы

# Две таблицы: клиенты и их заказы
customers = pd.read_csv("customers.csv")   # id, name, city
orders = pd.read_csv("orders.csv")         # customer_id, amount

# Соединяем по ключу и сразу считаем сумму заказов на клиента
result = duckdb.sql("""
    SELECT c.name, c.city, SUM(o.amount) AS total
    FROM customers c
    JOIN orders o ON c.id = o.customer_id
    GROUP BY c.name, c.city
    ORDER BY total DESC
""").df()

Задания

Базовый путь 🟢

Возьми любой CSV (или df из тома 1) и выполни через DuckDB три запроса: (1) выбрать строки по условию (WHERE), (2) сгруппировать и посчитать среднее/количество (GROUP BY), (3) отсортировать (ORDER BY). Сравни с тем, как ты делал бы это в pandas.

Продвинутый путь 🔵

Создай две связанные таблицы (например, ученики и оценки, или товары и продажи) и соедини их через JOIN, посчитав агрегаты по группам. Затем прогони один и тот же запрос по CSV напрямую (DuckDB умеет read_csv в SQL) — без загрузки в pandas.
