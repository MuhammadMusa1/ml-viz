Глава 3. Своя нейросеть руками

Цель главы 🎯

После этой главы ты сможешь описать модель через nn.Module, написать полный цикл обучения (пять шагов из «моста») и обучить свою первую сеть на PyTorch от начала до конца.

Пришёл главный момент фазы: соберём и обучим нейросеть на чистом PyTorch. Здесь сойдётся всё — тензоры, автоград, DataLoader и тот самый цикл обучения из «моста». После этой главы PyTorch перестанет казаться сложным.

Модель как класс: nn.Module

В Keras сеть была «стопкой слоёв» (Sequential). В PyTorch модель — это класс с двумя частями: __init__ (какие слои есть) и forward (как данные проходят через них). Это чуть больше кода, зато полный контроль над тем, что происходит внутри.

import torch
import torch.nn as nn

class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.flatten = nn.Flatten()          # картинка -> ряд чисел
        self.fc1 = nn.Linear(28*28, 128)     # полносвязный слой
        self.fc2 = nn.Linear(128, 10)        # выход: 10 классов
        self.relu = nn.ReLU()                # активация

    def forward(self, x):
        x = self.flatten(x)
        x = self.relu(self.fc1(x))           # слой + активация
        x = self.fc2(x)                      # выходной слой
        return x

model = Net()
print(model)

Сравни с томом 1: nn.Linear — это тот же Dense-слой, nn.ReLU — та же активation relu. Метод forward описывает путь данных через сеть — то, что в Keras задавалось порядком слоёв в Sequential. Больше свободы: здесь можно ветвить, объединять, делать что угодно.

Полный цикл обучения

А вот и сердце PyTorch — цикл обучения, который мы видели в «мосте». Теперь разберём каждую строку. Это тот самый паттерн, который ты будешь писать в каждом проекте тома 2, поэтому стоит понять его один раз навсегда.

import torch.optim as optim

model = Net()
loss_fn = nn.CrossEntropyLoss()                 # ошибка для классификации
optimizer = optim.Adam(model.parameters(), lr=0.001)  # оптимизатор

for epoch in range(5):                          # 5 эпох
    for images, labels in train_loader:         # по батчам
        optimizer.zero_grad()                   # 1. обнулить градиенты
        outputs = model(images)                 # 2. прогноз (forward)
        loss = loss_fn(outputs, labels)         # 3. посчитать ошибку
        loss.backward()                         # 4. градиенты (backward)
        optimizer.step()                        # 5. подкрутить веса
    print(f"Эпоха {epoch+1}, ошибка: {loss.item():.4f}")
ШагСтрокаЧто делает
1zero_grad()Обнулить градиенты с прошлого шага
2model(images)Прогнать данные вперёд, получить прогноз
3loss_fn(...)Измерить, насколько прогноз ошибочен
4loss.backward()Автоград считает градиенты (куда крутить веса)
5optimizer.step()Оптимизатор делает шаг: подкручивает веса

Вот и всё «страшное» обучение. Пять шагов, повторённых по всем батчам и эпохам. Keras прятал их в fit() — а теперь ты видишь и контролируешь каждый. Это тот же спуск с горы: измерили уклон (backward) и сделали шаг вниз (step).

Внимание, частая ошибка ⚠️

Порядок шагов важен и он всегда один и тот же: zero_grad → forward → loss → backward → step. Частые ошибки новичков: забыть zero_grad (градиенты накопятся), забыть optimizer.step (веса не обновятся — сеть не учится), перепутать порядок backward и step. Держи этот порядок как молитву, пока он не станет автоматическим.

Проверка на тесте

После обучения оцениваем модель — и здесь есть важный нюанс PyTorch: на проверке нужно отключить расчёт градиентов (они не нужны, только замедляют) и перевести модель в режим оценки.

model.eval()                        # режим оценки
correct = 0
with torch.no_grad():               # не считать градиенты на тесте
    for images, labels in test_loader:
        outputs = model(images)
        pred = outputs.argmax(dim=1)   # класс с макс. значением
        correct += (pred == labels).sum().item()

print("Точность:", correct / len(test_loader.dataset))

Полезно знать ℹ️

model.train() и model.eval() переключают режимы: на обучении нужны Dropout и BatchNorm (глава 4), на оценке — нет. torch.no_grad() отключает автоград на тесте — быстрее и экономит память. Забыть переключить режим — тонкая ошибка: сеть вроде работает, но метрики врут. Возьми в привычку: обучаешь — train(), проверяешь — eval() + no_grad().
